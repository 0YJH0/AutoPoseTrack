# AutoPoseTrack 中文训练与测试指南

本文对应当前首版单目 RGB 流程：YCB-V 单目标读取、MegaPose 全局初始化与
局部 refinement、连续 rollout、可恢复性标签，以及逻辑回归可靠性基线。
当前目标是验证完整研究管线，不是复现论文级性能。

## 1. 当前训练什么

MegaPose 的 coarse estimator、RGB refiner 和 scoring model 使用官方预训练权重，
当前全部冻结。实际训练的是位于 MegaPose 之上的可靠性分类器：

```text
RGB + GT bbox
  → 首帧 MegaPose 全局估计
  → 后续帧 MegaPose 局部 refinement
  → rollout 可观测特征
  → recoverability_features.npz
  → 可靠性分类器
```

GT pose 只用于生成离线 ADD/ADD-S 标签，不进入推理特征。首版标签使用过去
5 帧信息，判断当前或未来 10 帧内是否达到
`ADD(-S) < 0.10 × 物体直径`。

## 2. 下载并放置数据

### 2.1 源码

```bash
git clone --recurse-submodules https://github.com/0YJH0/AutoPoseTrack.git
cd AutoPoseTrack
git submodule update --init --recursive
```

### 2.2 YCB-V pilot 数据

当前 object 5 pilot 只需三个 BOP 压缩包：

- `ycbv_base.zip`：数据集信息和相机参数；
- `ycbv_models.zip`：CAD 模型、物体直径和对称性信息；
- `ycbv_test_bop19.zip`：BOP 选择的 900 个测试关键帧。

不需要下载 depth、PBR 或训练图像。当前流程只读取 RGB、相机内参、GT bbox
和用于离线评价的 GT pose。

在仓库根目录执行：

```bash
mkdir -p data/downloads data/bop
cd data/downloads

wget https://huggingface.co/datasets/bop-benchmark/ycbv/resolve/main/ycbv_base.zip
wget https://huggingface.co/datasets/bop-benchmark/ycbv/resolve/main/ycbv_models.zip
wget https://huggingface.co/datasets/bop-benchmark/ycbv/resolve/main/ycbv_test_bop19.zip

cd ../bop
7z x ../downloads/ycbv_base.zip
7z x ../downloads/ycbv_models.zip -oycbv
7z x ../downloads/ycbv_test_bop19.zip -oycbv
cd ../..
```

解压后必须存在：

```text
data/bop/ycbv/
├── models/models_info.json
├── models/obj_000005.ply
└── test/
    ├── 000050/rgb/
    └── 000052/rgb/
```

三个压缩包约 1.1 GB，解压后的当前数据约 1.6 GB，建议至少预留 5 GB。
以后研究完整连续视频时再下载 `ycbv_test_all.zip` 或 real training 数据；它们
不是当前 150 帧 pilot 的前置条件。

### 2.3 MegaPose RGB 权重

权重不要提交到 Git。推荐放在：

```text
data/megapose/megapose-models/
```

执行：

```bash
export YCBV_ROOT="$PWD/data/bop/ycbv"
export MEGAPOSE_DATA_ROOT="$PWD/data/megapose"

docker compose --profile gpu build megapose
docker compose --profile gpu run --rm megapose nvidia-smi
docker compose --profile gpu run --rm megapose \
  python -m megapose.scripts.download --megapose_models
```

当前只使用 `megapose-1.0-RGB`，禁止 RGB-D checkpoint 和 ICP。

## 3. 运行最小测试

### 3.1 单元测试

```bash
docker compose build core
docker compose run --rm core python -m pytest -q
```

### 3.2 单帧 GPU 测试

输出目录不可已存在，重复运行时需更换名称。

```bash
export YCBV_ROOT="$PWD/data/bop/ycbv"
export MEGAPOSE_DATA_ROOT="$PWD/data/megapose"

docker compose --profile gpu run --rm megapose \
  bash scripts/run_megapose_headless.sh \

  --renderer-workers 1 --batch-size 64 \
  --output outputs/megapose_object5_smoke
```

查看结果：

```bash
cat outputs/megapose_object5_smoke/metrics.json
```

## 4. 生成训练数据

### 4.1 运行约 150 帧连续 rollout

scene 50 和 scene 52 各包含 object 5 的 75 个关键帧：

```bash
docker compose --profile gpu run --rm megapose \
  bash scripts/run_megapose_headless.sh \
  python -m scripts.run_ycbv_rollout \
  --dataset-root /data/ycbv \
  --object-id 5 \
  --sequence 50 --sequence 52 \
  --model-name megapose-1.0-RGB \
  --refiner-iterations 2 \
  --renderer-workers 1 --batch-size 64 \
  --output outputs/ycbv_object5_rollout_150
```

首帧走全局估计，后续帧以上一帧 pose 为初值走局部 refinement。输出为：

```text
outputs/ycbv_object5_rollout_150/
├── rollout.csv
└── summary.json
```

### 4.2 生成特征和序列划分

```bash
docker compose run --rm core \
  python -m scripts.build_recoverability_features \
  --rollout outputs/ycbv_object5_rollout_150/rollout.csv \
  --diameter-m 0.196463 \
  --history-frames 5 --future-frames 10 \
  --success-fraction 0.10 \
  --train-sequence 000050 \
  --validation-sequence 000052 \
  --output outputs/ycbv_object5_features_150
```

输出：

```text
outputs/ycbv_object5_features_150/
├── recoverability_features.npz
└── sequence_split.json
```

划分单位是完整 scene，不允许把相邻帧随机分入训练集和验证集。当前没有独立
test scene：scene 50 用于训练，scene 52 用于验证。

## 5. 开始训练

把特征目录只读挂载到容器的 `/data/features`：

```bash
export FEATURE_DATA_ROOT="$PWD/outputs/ycbv_object5_features_150"
docker compose build training
docker compose run --rm training \
  python -m scripts.train_reliability \
  configs/experiments/train_reliability_logreg_pilot.yaml
```

训练产物：

```text
outputs/reliability_logreg_ycbv_object5_pilot/
├── model.npz
├── metrics.json
├── history.json
├── config.yaml
├── manifest.json
└── logs/
```

训练命令会同时计算 scene 50 的训练指标和 scene 52 的验证指标：

```bash
cat outputs/reliability_logreg_ycbv_object5_pilot/metrics.json
tail -n 30 outputs/reliability_logreg_ycbv_object5_pilot/logs/train.log
```

## 6. 开始测试

当前需要区分三类测试：

1. 代码测试：运行 `pytest`。
2. 位姿链路测试：运行单帧测试或对 scene 52 单独运行 rollout。
3. 可靠性验证：训练命令已在完整 scene 52 上计算验证指标。

单独测试 scene 52 位姿链路：

```bash
docker compose --profile gpu run --rm megapose \
  bash scripts/run_megapose_headless.sh \
  python -m scripts.run_ycbv_rollout \
  --dataset-root /data/ycbv \
  --object-id 5 --sequence 52 \
  --output outputs/ycbv_object5_scene52_test

cat outputs/ycbv_object5_scene52_test/summary.json
```

当前没有独立测试集，因此不能把 scene 52 验证指标称为最终 test 结果。正式
实验需要增加更多完整序列，并固定 train/validation/test 三组 scene。

## 7. 当前限制

- 使用 GT bbox，尚未接入真实 RGB detector。
- MegaPose 固定，不训练 coarse/refiner 网络。
- 150 帧自然 rollout 标签约为 132:18，scene 50 只有一个负样本。
- 当前逻辑回归只验证接口与日志，不能支持性能结论。
- 下一步需要种子固定的 SE(3) 扰动 rollout，以覆盖恢复边界。
- 输出目录禁止覆盖；重新运行时应使用新名称或先归档旧结果。

## 8. 磁盘空间建议

| 内容 | 建议预留 |
|---|---:|
| YCB-V pilot 数据（含压缩包） | 5 GB |
| MegaPose 权重 | 2 GB |
| Docker 镜像和构建缓存 | 15–25 GB |
| rollout、日志和扰动实验 | 10 GB 以上 |
| 当前方案合计 | 至少 40 GB |

若下载完整 YCB-V real/PBR 数据或保存大量扰动 rollout，建议预留
100–150 GB。
